# 会場図・写真から3D化し、リアルなヒートマップを作れるか

> 作成 2026-08-09。問い =「会場全体の全体図や会場の写真から3Dモデリングし、
> さらに日時・天気・太陽の方向・風向きなどの情報からリアルなヒートマップを作成することは可能か」
>
> **結論から: 可能。ただし「写真から3D」と「図面から2.5D」は難易度が10倍違う。**
> 今回のハッカソンでは後者で十分な絵が出ます。試作は `/heatmap` で動いています。

---

## 1. 結論

| やりたいこと | 実現性 | 今回やるか |
|---|---|---|
| 会場**図面**から建物の輪郭と高さを取り、影を計算する | ✅ **試作が動いている** | やる（優先01と同じ作業） |
| 日時・緯度経度から**正確な太陽位置**を出す | ✅ **実装済み・検証済み** | 済 |
| 気温・湿度・雲量・風向・風速から**格子単位のWBGT** | ✅ **試作が動いている** | 済（校正は継続） |
| 会場の**写真**から3D形状を復元（フォトグラメトリ） | △ 技術的には可能だが、撮影・処理・検証で数日 | **やらない**（受賞後） |
| PLATEAU（国交省の3D都市モデル）を使う | ○ データは公開済み。会場外の街区に効く | 余力があれば（優先06相当） |
| CFD（数値流体力学）で風を厳密に解く | ✕ ソルバの構築と検証で数週間 | やらない |

**要点**: 「リアルさ」を出しているのは3Dモデルの精密さではなく、**太陽位置が本物であること**と**地表面・風・影を分けて扱っていること**です。だから2.5Dで足ります。

## 2. 今すでに動いているもの（`/heatmap`）

### 太陽位置は実計算

NOAAの近似式で、緯度経度・日付・時刻から方位角と高度を求めています。

**検証**: 東京の冬至の南中高度が **30.7°**。理論値 `90 − 35.65 − 23.44 = 30.9°` と一致。
8/9の日の入りも18:45で実際と整合します。月・日・時刻のスライダーを動かすと、太陽の向きと影が本当に変わります。

### 建物の影は幾何計算

建物の footprint を太陽と反対方向に `高さ ÷ tan(太陽高度)` だけ押し出し、元の形と合わせた**凸包**をとる。これが影の多角形です。これは**平屋根・平坦地を仮定した2.5Dの押し出し**で、フォトグラメトリの3Dメッシュは要りません。

### ヒートマップは125×88の格子

1セルずつ以下を積んでいます。

```
WBGT = 日陰基準値
     + 直射による上昇（日射強度 × 日なた率 × 地表面の材質）
     + 日陰でも受ける地面からの再放射
     − 風による冷却（風速の平方根 × 風の当たりやすさ）
```

| 要素 | 扱い |
|---|---|
| 地表面の材質 | アスファルト1.25 / デッキ1.05 / 芝0.62 / 水面0.28 |
| 建物風下の淀み | 風上へレイを飛ばし、建物に当たるまでの距離で換気の悪さを決める |
| 風下への移流 | 風上セルの値を3回混ぜ込み、熱が風下へ流れる |

### WBGTの式（ここは正直に）

**正式なWBGTは黒球温度の実測が必要で、気温と湿度だけからは求められません。**
よく引用される屋内近似式 `0.567·Ta + 0.393·e + 3.94` を最初に使いましたが、34℃/65%で36.8℃となり環境省の暑さ指数表より数℃高く、**全面が「危険」で潰れました**。

日陰・弱風時が環境省の区分と整合するよう校正した近似に置き換えています。

```
WBGT_日陰 ≒ 0.70 × 気温 + 0.06 × 湿度 + 0.8
```

現在の出力レンジは **27.1〜31.1℃**。警戒／厳重警戒／危険の3帯が分布します。
この「実計算・校正した近似・簡易モデル・未実装」の区別は**画面上に常時表示**しています。審査で聞かれたときに、この一枚を指させる状態にしておくのが目的です。

## 3. 「写真から3D」を今回やらない理由

| 段階 | 必要なこと | 所要 |
|---|---|---|
| 撮影 | 会場を周回して数百枚。重なり率60%以上、露出固定 | 半日＋現地 |
| 復元 | COLMAP等でSfM→点群→メッシュ。GPUが要る | 数時間〜1日 |
| 整合 | 実寸へのスケール合わせ、北の向き合わせ、地面の平面推定 | 半日 |
| 単純化 | メッシュのままでは影計算が重い。結局 footprint + 高さに落とす | 半日 |
| 検証 | 復元した形が実際と合っているかの確認 | — |

**最後の行が問題です。** どれだけ苦労しても、影の計算に使うのは結局「輪郭と高さ」だけ。**図面から直接それを取れば、同じ絵が1/10の手間で出ます。**

写真からの3D復元は、投じる手間に対して得られる精度の差が小さく、今回のスコープでは採用しません。

**ただし「やらない」ではなく「順番が後」です。** §5に今後のロードマップとして書いています。

## 4. 次にやること — 図面 → Venue JSON（優先01と同じ作業）

**ここがハッカソンの本命です。** UI刷新と④AIである必然性が同じ作業になります。

```
会場図面PDF / 写真
      ↓  OrcaRouter · Vision（image_url）
      ↓  OrcaRouter · Structured Outputs（json_schema で Venue 型を強制）
Venue JSON  { zones: [...多角形], buildings: [{footprint, height}], ground: [...] }
      ↓  既存の計算（変更不要）
影の多角形 → 日陰率 → ヒートマップ → 混雑予報 → 雑踏警備計画書
```

**なぜこれが「AIである必然性」の証明になるのか**

- 会場図面は会場ごとに様式がバラバラで、ルールベースでは会場ごとに作り直しになる（＝事業としてスケールしない）
- 過去の警備計画書・ヒヤリハット報告も非構造の自然言語
- **2会場目以降の立ち上げコストを決めるのがこの読解**であり、ここだけはLLMでないと成立しない

### 実装メモ

| 項目 | 内容 |
|---|---|
| モデル | `google/gemini-2.5-pro`（Vision + json_schema 対応）／ fallback `openai/gpt-4o` |
| ⚠️ 注意 | **Anthropicは `response_format` 非対応**。Claudeで構造化するなら `tool_use` パターン |
| 高さの推定 | 図面に高さは書いていないことが多い。**階数表記や用途（ホール/駐車場/仮設テント）から推定させ、UIで人が修正できるようにする**。ここは人が判を押す前提の設計 |
| 縮尺 | 図面のスケールバーか、既知の寸法（ステージ幅など）を1つ与えて実寸に合わせる |
| 方位 | 図面の方位記号を読ませる。無ければ住所から推定して人が確認 |
| 座標 | 住所 → 緯度経度（ジオコーディング）→ `solar.ts` に渡す |

**押さえどころ**: 図面読解は**会場ごとに1回きり**です。ここに上位モデルを使っても、1イベント当たりの原価はほとんど動きません。⑥の説明としても筋が通ります。

## 5. その先（受賞後のロードマップ）

| 段階 | 内容 | 前提 |
|---|---|---|
| A | **PLATEAU の3D都市モデル**を会場外に使う。駅・商店街・路地の建物形状が公開データで手に入る。会場外予報の精度が上がる | データ取得と座標変換 |
| B | **実測でのキャリブレーション**。会場に黒球温度計を数点置き、モデルの出力と突き合わせて係数を校正する。これで「近似」が「実測に合った近似」になる | 現場での計測 |
| C | **写真からの3D復元**。仮設ステージやテントなど図面に無い構造物を拾う。段階Bの後で初めて意味が出る | GPU・撮影体制 |
| D | **簡易CFD**。建物間の風の巻き込みを解く。段階Bの検証データが揃ってから | 数週間 |
| E | **群集の発熱**を熱収支に入れる。1人あたり約100Wの顕熱。密度マップと結合すると「混雑が暑さを作る」が表現できる | 混雑モデルとの結合 |

**Eが構想として最も面白い**です。混雑と暑熱を別々に扱っている既存ツールに対して、「人が集まるから暑くなり、暑いから人が動く」という相互作用まで踏み込める。⑧次世代性・独創性の材料になります。ただし今回は**やらない**——検証できない数字を出すほうが減点だからです。

## 6. 今回のデモでどう見せるか

1. **`/heatmap` で日付を12月にする** → 影が一気に長くなる。太陽位置が本物であることが一目で伝わる
2. **時刻を動かす** → 影が回り、風下に熱がたなびく
3. **風向を変える** → 建物の風下に熱がこもる様子が動く
4. **「この計算の内訳」パネルを指す** → 実計算・校正した近似・未実装を自分から開示する

4番が効きます。**限界を自分から言えるチームは、数字を信用してもらえます。**
